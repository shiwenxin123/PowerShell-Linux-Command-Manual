    • 从命令速查到自动化巡检: 一个中文运维知识库的开源化实践

    正文¶

    如果你经常在 Windows PowerShell、Linux、国产 Linux、容器平台和云服务器之间切换，应该会遇到一个很现实的问题: 命令很多，但真正排障时并不只是“记住命令”。

    线上值班时，我们更需要的是:

    • 快速知道先查什么。
    • 明白哪些命令只读、哪些命令有风险。
    • 能把排查结果整理成报告。
    • 遇到常见故障时，有一条相对稳定的排查路径。
    • 新同事也能按文档完成基本定位。

    基于这些场景，我整理并开源了一个中文项目: Windows PowerShell 与 Linux 常用命令手册。

    项目地址:

    • GitHub: https://github.com/shiwenxin123/PowerShell-Linux-Command-Manual
    • 在线文档: https://shiwenxin123.github.io/PowerShell-Linux-Command-Manual/
    • Release: https://github.com/shiwenxin123/PowerShell-Linux-Command-Manual/releases/tag/v2.16.0

    这个项目解决什么问题¶

    这个项目不是单纯罗列命令，而是把常见运维工作拆成几个入口:

    场景 内容
    快速查命令 PowerShell、Linux、Bash、curl、jq、SSH 等速查
    值班排障 磁盘、CPU、端口、DNS、证书、Nginx、systemd 等案例
    国产 Linux 银河麒麟、统信 UOS、离线源、架构兼容和版本差异
    容器平台 Docker、Kubernetes、Ingress、Pod、Node、CoreDNS 排障
    自动化巡检 Linux/Windows 巡检脚本，支持 text、markdown、json
    开源维护 Roadmap、Good First Issues、Release 检查清单和运营手册

    v2.16.0 做了哪些增强¶

    v2.16.0 是项目从“命令手册”走向“可维护知识库 + 自动化工具”的一个版本。

    1. 主手册最终收口¶

    早期根目录主手册保存了几千行完整正文，适合初期积累，但随着专题页越来越多，继续维护一份超长正文会带来重复和不一致。

    现在根目录主手册已经收口为:

    • 总导航。
    • 历史说明。
    • 专题入口。
    • 贡献入口。

    真正的命令正文进入专题页、路线页和故障案例库。

    2. 巡检脚本模块增强¶

    Linux 和 Windows 巡检脚本现在支持更多模块:

    模块 说明
    system 系统版本、运行时间、内存等
    disk 磁盘空间、inode 或驱动器信息
    network 监听端口和路由
    service 异常服务或未运行服务
    process CPU 和内存占用较高的进程
    package 包管理器、软件源、已安装包或仓库状态
    security SSH、防火墙、安全策略、Defender 等基础状态
    container Docker、containerd、Kubernetes 客户端或节点状态
    log 系统错误日志、journal 占用、Windows 事件日志摘要

    Linux 示例:

    bash scripts/linux-health-check.sh --module security --format json
bash scripts/linux-health-check.sh --module log --format markdown --output reports/linux-log.md

    Windows 示例:

    .\scripts\windows-health-check.ps1 -Module package -Format json
.\scripts\windows-health-check.ps1 -Module container -Format markdown -OutputFile reports\windows-container.md

    JSON 输出统一包含:

    • metadata
    • modules
    • summary
    • errors

    这意味着巡检结果可以被 CI、内部平台或二次脚本继续消费。

    3. 真实生产案例继续扩展¶

    这次补充了 5 个更贴近生产现场的案例:

    • 网关超时。
    • 负载均衡健康检查失败。
    • 消息队列连接失败。
    • 数据库连接池耗尽。
    • Prometheus 告警规则误报。

    每个案例都按统一结构编写:

    现象 -> 快速判断 -> 排查命令 -> 常见原因 -> 处理建议 -> 高危提醒 -> 相关专题

    这样做的好处是，值班时不用从长文里找线索，可以直接按故障现象进入排查路径。

    4. PDF 发布自动化¶

    项目新增了 PDF Export GitHub Actions 工作流，可以手动触发导出重点页面 PDF。

    当前会导出:

    • 文档站首页。
    • 命令速查表。
    • 运维值班路线。
    • 巡检脚本工具化说明。
    • 真实故障案例库。

    这些 PDF 可以作为 Release 附件，也可以放进内部知识库。
